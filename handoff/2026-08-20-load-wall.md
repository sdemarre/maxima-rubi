## Decision (2026-08-22): raise the TLS limit at runtime

Measured basis (probes committed under `probes/load_wall/`, all run
2026-08-22 on Maxima 5.50.0 / SBCL 2.6.7):

- **The accounting** (`probe-tls-calibration.out`): each
  defmatch/matchdeclare slot is one SBCL special var = one 16-byte thread-
  local-storage slot = 8 index units of `sb-vm::*free-tls-index*`. A fresh
  maxima process starts at 8,516 units (thread-struct base + maxima's own
  startup vars). The installed core's baked-in limit is **~4,098 special
  vars** (plain-pattern boundary: 1,516 load / 1,517 FATAL) — which is
  exactly why the default load dies at ~rule 310. The cap is a *count*, not
  memory; it is tunable at runtime via `maxima -X "--tls-limit N"` (the
  flag takes two argv tokens, not `--tls-limit=N`).
- **The cost curve** (`probe-load-curve.out`): class-1 rules cost
  **9.64 special vars per rule** on average (per-file 1..17; 2,269 rules
  measured directly in one process, the 436 rules of the 6 parse-broken
  files estimated at the mean). Required limits, fresh-process baseline
  included: class 1 (2,710) ≥ ~27.2k; always-loaded layer (2,805) ≥ ~28.1k;
  **all loaded Rubi classes (7,432 — T1 count; classes 2–9 extrapolated at
  the class-1 mean) ≥ ~72.7k**.
- **The parse sweep** (`probe-parse-sweep.out`): **6 of 67 generated
  class-1 files are parse-broken** — `1_1_3_1` (two spots), `1_1_3_2`,
  `1_1_3_7`, `1_2_1_1`, `1_2_3_4`, `1_4_3` — unparenthesized `==`/`=` mixed
  with `and`/`or`, a missing `)`, one LOGICAL/ALGEBRAIC mix. 436 rules
  affected; the T4 generator needs a fix pass (acceptance: sweep to zero,
  curve to a clean 67-file run). The old probe's per-file check had a false
  positive here (batch mode exits 0 and still prints after a mid-file
  syntax error) — fixed in `probe-load-wall.run` part 2.

Decision: run every maxima process that loads rule files with
`-X "--tls-limit 100000"` — 72.7k × 1.37, headroom for the unmeasured
classes 2–9 and future build drift (the probes self-flag if the
accounting moves). Recorded as a standing instruction in AGENTS.md
("Loading rule files: the TLS limit"). At that limit the full class-1
load succeeds (probe-load-curve.out: clean 60-file run + core).

## The load wall (the problem) — measured on both builds

- **At the DEFAULT limit, one maxima process holds ~294–361 class-1 rules.
  The full class-1 set is 2710 — a ~7.5× gap.** No per-rule optimization
  closes a 7.5× gap. (Still true at the default limit — and now a
  non-issue: the runtime-limit decision above.)
- **Root cause** (confirmed in the maxima source): each `defmatch`/
  `matchdeclare` allocates **SBCL special (dynamic) variables**
  (`src/matcom.lisp`, `declare (special ...)` at lines ~92, 107, 111, 356,
  418, 421, 438, 519, 539, 605). The process cap is **~1200–1600** such
  variables → **"Thread local storage exhausted"** (an **uncatchable** FATAL)
  once exceeded.
- Maxima already fights this for its own rules via `*rule-symbol-pool*`
  (`src/globals.lisp:1914-1916` — recycles symbols from deleted rules). That is
  why **`unload` releases the budget** (measured: 4×1200 patterns with unloads
  all load).
- **5.50 did NOT raise the cap.** It is a *capacity* limit, not a *speed* limit
  — 5.50's matcher-speed improvements don't touch it. Re-measured identical on
  5.50.0 (the `.out` is stamped 5.50.0).
- **ANSWERED 2026-08-22 (probe-tls-calibration):** the cap is a *count* of
  special variables — SBCL's `--tls-limit` (baked into the installed core at
  save, ~4,098), overridable at runtime via `maxima -X "--tls-limit N"`.
  Not a memory/heap issue.
- Full measurement: `probes/load_wall/` — the six-part, self-flagging wall
  probe (full load FATAL; per-file parse, now parse-error-aware; 1200 load /
  1600 die; unload releases; prefix 7 files/294 rules; prefix 8/361 FATAL)
  plus the 2026-08-22 additions (calibration, load curve, parse sweep), all
  stamped with `build_info()`.

## Direction 2 — the "large if-then-else" strategy (Rubi 5)

Replace pattern matching with compiled if-then-else code. **Read the reference
first: `reference/rubi-5/Plan for Implementing Rubi 5.md` + `Rubi-5.m`.**

- Rubi 5 compiles Rubi 4's 3000+ algebraic pattern rules into **42 `Int*nnn`
  functions**, each a **single deeply-nested if-then-else construct** —
  explicitly *not* pattern matching. That is the key: **no `defmatch`/
  `matchdeclare` → no special variables → no TLS cap → all rules fit in one
  process.**
- The `Int[u, x]` dispatcher categorizes `u` (a type number: 1=linear,
  2=quadratic, 3=cubic, 4=quartic, 5=binomial, 6=trinomial, 7=unknown) and
  descends a **42-leaf if-then-else decision tree** to call the right
  `Int*nnn`. Products `Int[f^m g^n …]` sort the base/degree pairs by type
  number, then descend the tree.
- Only **~42 pattern rules** remain (vs 2710) — trivially within the cap.
- `Int111` and `Int121` are fully implemented in `Rubi-5.m` (manually compiled
  from Rubi 4 `1.1.1` and `1.2.1`); the other 40 are `Defer[Int*nnn]`
  placeholders. The author says a pattern-matching→if-then-else **compiler** is
  the intended automation, and that he has programs translating if-then-else
  decision trees from Mathematica to **Maxima** syntax.
- Implication for our codebase: this **fundamentally changes the runner and the
  generator's output** — instead of emitting `matchdeclare`/`defmatch`/
  `_mr_rule_*`, the generator would emit if-then-else `Int*nnn` functions + a
  decision-tree dispatcher. Tasks 7–10 (utility layer, corpus driver, full
  run) would be re-scoped around it.

- **Any maxima process that loads rule files runs with

  two argv tokens (`--tls-limit N`, not `--tls-limit=N`).
- Real Common Lisp from a maxima batch (the idiom the TLS probes use):
  `:lisp` lines are read all-first by the CL reader in the *current* lisp
  package (maxima's reader hijacks `load`/`read`/`open` — a `:keyword`
  there breaks — but not the `:lisp` lines); a `:lisp (setf *package*
  (cl:find-package :cl))` line switches subsequent lines' reads to CL
  without touching maxima-syntax lines; export + `cl:`-qualify functions
  called across the switch. The TLS water level is `sb-vm::*free-tls-index*`
  (mask the sign-bit semaphore; 8 index units per special var).
- A mid-file syntax error during a sibling `load` makes the *outer* batch
  file silently stop being read (exit 0; no further lines execute), and
  ordinary syntax errors also end a batch with exit 0 — never trust rc
  alone for "the file loaded" (grep the log for "incorrect syntax" /
  "could not load"; `probe-parse-sweep.run` is the reference check).
- House traps (see T2 / plan Global Constraints): `rules` is a protected
  symbol; a quoted symbol nested in a call's arg list is a batch parse error;
  `?fboundp` doesn't see Maxima `:=` functions; `coefficient`/`degree`/
  `maxexpt` are nouns in this build; booleans flow through three-valued
  `is()`; `errcatch` returns `[RESULT]` on success, `[]` on error.
